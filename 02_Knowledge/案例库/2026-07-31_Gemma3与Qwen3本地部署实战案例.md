# Gemma3与Qwen3本地部署实战案例

## 背景

2026-07-31，按"入戏"提供的端侧部署方案，在 8GB Mac（macOS 26.5.2，Apple Silicon，8 核）上用 llama.cpp 部署 Google Gemma 端侧模型，目标是接入 Trae 做本地 agent。全程 3.5 小时，下载 4 个模型 14.5GB，实测后清理还原。

## 过程

### 阶段一：安装与下载（11:20-12:09）
- `brew install llama.cpp` 秒装 v10180（arm64_tahoe bottle），依赖 libomp/ggml/openssl@3
- 模型下载：Gemma 3 4B Q4_K_M 2.49GB（hf-mirror，速度慢约 0.9MB/s）、Gemma 3n E4B 4.54GB + Qwen3 8B + Qwen3 4B（ModelScope，稳定高速）
- 关键情报：技能库提示 hf-mirror 大文件不稳、ModelScope 首选——实测验证成立

### 阶段二：Gemma 3 4B 测试（失败）
- llama-server 全 GPU 启动成功，但 **工具调用不可用**：忽略 tools、编造"墨迹天气"假数据
- 大 context 实测：11508 tokens prompt 处理耗时 91.5s（125 t/s → 随长度衰减），eval 8.88 t/s

### 阶段三：Qwen3 8B 测试（能力达标，速度崩盘）
- 全 GPU（-ngl 99 / 40）→ Metal OOM（`Insufficient Memory 00000008`）
- -ngl 18（GPU/CPU 各半）→ 启动成功，**工具调用完美**（`finish_reason: tool_calls`，输出 `{"city":"北京"}` + 思考过程）
- 但速度只有 **3 t/s**，Trae 里不可用
- Trae 实际请求体量很大（12435/12717 tokens），进一步加重 8GB 负担

### 阶段四：结论与清理（14:34 结束）
- 结论：**8GB Mac 本地 agent 正解 = Qwen3-4B**（工具调用强化 + 全速 25+ t/s）
- 清理：关闭服务 → `rm -rf ~/models`（释放 14.5GB）→ `brew uninstall llama.cpp ggml` → 删启动脚本 → 验证无残留

## 关键结果

| 模型 | 工具调用 | 8GB 可用性 | 速度 |
|---|---|---|---|
| Gemma 3 4B | ❌ 幻觉 | ✅ 全 GPU | ~9 t/s（大context） |
| Gemma 3n E4B | 未测（4.54GB 权重偏紧） | 边缘 | - |
| Qwen3 8B | ✅ 完美 | ❌ OOM / 3 t/s | 3 t/s |
| Qwen3 4B | ✅（系列强化） | ✅ | 25+ t/s（预期） |

## 经验教训

1. **8GB 机器别碰 8B 模型**——调参（-ngl）只能换稳定，换不来速度
2. **工具调用是 agent 模型的硬指标**，选型前必须实测，不能看宣传
3. **实验要有清理预案**——4 个模型 14.5GB 一次实验就占满磁盘 40%，用完即删
4. 经验已沉淀进 llama-cpp 技能（Gemma 工具调用不可用 / Qwen3 是 agent 正解 / 8GB 铁律 / Trae 接入参数）
