# 小红书梵高风格图文流水线运营心法

**背景**

Hermes每日运行5个xhs-vangogh cron任务（多账号），通过mmx生成梵高融合风图片，结合BHR（Browser）自动发布小红书。整个流程涉及图片生成、浏览器自动化、飞书通知三大系统协同。2026-05-20当日成功发布"手写日记"题材，这是该流水线的第34个题材。

**核心洞察**

**一、题材选择决定内容差异化的天花板**

题材是流量的第一入口。梵高融合风的优势在于：视觉风格强烈、辨识度高、与日记/情感类文案天然契合。当前已用34个题材，涵盖竹林小径、手工艺人、手写日记等人文情感类主题。题材选择原则：
- 强视觉叙事：适合梵高笔触呈现（如风景、人物劳作）
- 情感共鸣：搭配"写下来的日子才算真正活过"等金句
- 避免纯知识类（梵高风格不适配严肃知识科普）

**二、Chrome DevTools WebSocket路径刷新机制（关键技术踩坑）**

BHR（Browser）通过Chrome DevTools Protocol控制浏览器，WebSocket路径（`webSocketDebuggerUrl`）会随Chrome重启变化。旧路径存在`/tmp/chrome_xhs.log`中，但下次启动时已失效，导致BHR报404。

正确修复流程：
```bash
# 1. 获取当前有效路径
curl -s http://127.0.0.1:9543/json/version

# 2. 提取 webSocketDebuggerUrl 并更新 /tmp/chrome_xhs.log
# 3. 重试发布
```

**三、多账号轮换策略**

5个cron任务对应多账号，题材避免重复，形成"同一风格+不同题材+不同账号"的矩阵效应。历史题材记录是避免重复的基础数据。

**四、飞书全链路通知**

每步骤均触发飞书通知：生成开始→图片产出→发布成功。通知采用`send_text`+`send_images`+`send_audio`（BGM+TTS混音）三段式，让运营者实时掌握流水线状态。

**对Jerry的意义**

这套流水线的核心价值不是"发小红书"，而是验证了"AI生成+浏览器自动化+多系统协同"的 Agentic Workflow 范式。当一个cron任务能自动完成从内容生成到平台发布再到效果通知的全链路时，人力只需在素材质量上把关。未来可将这套范式迁移到其他平台（抖音、公众号）或切换内容类型（知识科普、产品种草）。

**延伸思考**

如果将梵高风格换成写实摄影风格，题材选择逻辑如何调整？写实风格更适合产品展示、教程类内容，但需要解决AI图片"一眼假"的问题——可能需要真人出镜或实拍素材做底。另一个方向是横向扩展到视频：用梵高风格图集生成PPT式视频（mmx图+剪映配音），内容形态升级但核心题材选择逻辑不变。
