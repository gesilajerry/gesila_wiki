# 定时新闻简报流水线设计

**背景**
Hermes 每日运行21个cron任务，覆盖AI热点、财经新闻、垂直行业（半导体、原子级制造、MLCC产业链）四大领域，在早中晚三个时间窗口自动生成并推送简报。这套流水线的设计思路值得抽象为可复用的方法论。

**核心洞察**

**设计原则：多领域 × 多时间点 × 分级处理**

```
领域层（垂直追踪）
├── AI热点    → mmx search 全网搜索
├── 财经新闻  → 定向信源 + 结构化摘要
├── 半导体   → 产业链上下游联动追踪
└── MLCC/原子级制造 → 细分赛道深度覆盖

时间层（分发节奏）
├── 晨间（06:00-08:00）  → 昨日总结 + 今日展望
├── 午间（11:00-13:00）  → 盘中动态
├── 傍晚（17:00-19:00）  → 午后汇总
└── 晚间（21:00-23:00）  → 全天回顾 + 精选

输出层（多渠道）
├── 飞书推送 → 即时触达（chat_id定向）
├── 内网博客 → 沉淀归档（分类标记）
└── 小红书   → C端图文（视觉化）
```

**垂直领域追踪的三个层次：**

1. **宏观层（AI/财经）** — 大范围搜索，按相关性排序，过滤旧闻，8-10条/期
2. **中观层（半导体/新能源）** — 产业链视角，从材料到终端联动追踪
3. **微观层（MLCC/原子级制造）** — 细分赛道，深挖供需关系和厂商动态

**mmx search 在简报中的使用模式：**
```python
def search_briefing(keywords, max_results=5, max_total=12):
    all_results = {}
    for kw in keywords:
        try:
            results = mmx_search(kw, max_results=max_results)
            for r in results:
                key = r['title'][:30]  # 用 title 做去重 key
                if key not in all_results:
                    all_results[key] = r
        except Exception as e:
            print(f"搜索 '{kw}' 失败: {e}")

    items = list(all_results.values())
    items.sort(key=lambda x: x.get('date', ''), reverse=True)
    return items[:max_total]
```

多关键词合并去重保证内容丰富度，时间排序确保时效性。

**对Jerry的意义**
这套流水线让 Hermes 实现了"开机即运转"的自动化状态。每天21个任务基本覆盖了投资研究最需要的几个垂直领域，且互不干扰。理解这个设计框架后，可以新增其他垂直领域（如生物医药、高端制造）的追踪，只需要定义：搜索关键词 + 分类group_id + 推送时间。

**延伸思考**
目前各领域是独立运行的，未来可以考虑：
- **交叉引用**：当AI热点中提到某个半导体公司时，自动关联MLCC产业链简报
- **紧急插播**：当重大政策/事件发生时，触发即时简报而非等待定时
- **效果追踪**：记录每次推送的阅读量，优化推送时间和内容长度
