# 飞书+Koala双节点内容分发工作流

**背景**
2026年5月27日Hermes cron任务执行了14个内容发布任务，覆盖财经晨报、MLCC产业链晨报、原子级制造科研晨报、半导体产业晨报、梵高图文日更等。每条内容都同时发布至两个平台：Koala内网博客（知识沉淀）+ 飞书会话通知（实时触达）。

**核心洞察**

双节点工作流是Hermes内容分发的事实标准范式：每个内容生成任务完成后，同时触发两个动作——推送到Koala博客归档（沉淀），推送飞书通知（触达）。

**节点一：Koala博客发布**
- 用途：内容资产的持久沉淀，跨团队知识共享
- 分类体系：市场销售-专业知识、综合管理-专业知识等一级分类
- 格式要求：Markdown，保留原始标题、日期、内容结构
- 入口：Koala内网博客系统（192.168.30.198:8443）
- 验证：推送后系统返回发布成功状态

**节点二：飞书IM通知**
- 用途：实时触达相关人员，推动内容消费
- 发送方式：通过飞书开放平台IM API，使用tenant_access_token认证
- 目标会话：oc_1e92781cdf15f71fad7dcd8d5d386e76（主通知群）
- 消息格式：post消息格式，支持emoji、分行、换行；不支持加粗和表格
- 验证：飞书API返回发送成功状态

**双节点工作流的价值**

1. **知识沉淀 vs 实时触达分离**：Koala确保内容不丢失、可检索；飞书确保相关人第一时间看到
2. **发布即通知**：无需人工干预，cron任务自动完成全链路
3. **双重成功验证**：Koala和飞书都返回成功状态，任何一方失败都可追溯
4. **日志可审计**：每次推送结果都写入cron输出日志，形成完整的执行证据链

**对Jerry的意义**
这一工作流使Hermes成为真正意义上的"无人值守内容工厂"。Jerry无需登录任何系统，内容自动生成→自动发布→自动通知。每天14个任务的稳定执行，靠的是双节点工作流的标准化——每个新内容只需确定：①Koala分类（决定沉淀位置）、②飞书发送范围（决定触达人群）、③内容格式（Markdown）。

**延伸思考**
双节点模式可扩展为"多节点分发"：除Koala+飞书外，可增加微信群发、邮件列表、Twitter等渠道。关键原则是：内容生成层（LLM输出）与分发层（各平台API）解耦，新增分发渠道只需在分发层增加适配器，不影响内容生成逻辑。这正是Hermes cron任务设计的核心思路——每个任务专注一件事，通过标准化的输出格式串联多个下游。
