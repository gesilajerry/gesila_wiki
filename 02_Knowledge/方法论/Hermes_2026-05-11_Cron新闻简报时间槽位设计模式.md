# Cron新闻简报的时间槽位设计模式

**背景**

2026-05-11 的21个cron任务分布显示，不同内容类型有不同的最优发布节奏：AI热点4次/天、财经新闻4次/天、MLCC和原子级制造各2次/天、单一主题的半导体热点2次/天。这不是随机分布，而是遵循一套可复用的时间槽位设计原则。

**核心洞察**

Cron新闻简报的时间编排遵循"媒体时间表"逻辑：高频泛内容用整点推进，低频垂直内容用晨晚双峰

**时间槽位分布规律：**

```
泛内容（AI热点、财经）→ 每6-8小时一次，全天均匀分布
  AI热点: 04:00 / 12:00 / 18:00 / 22:00（每8小时，4次）
  财经:   02:30 / 08:30 / 14:30 / 20:30（每6小时，4次）

垂直内容（MLCC、原子级制造）→ 晨间+傍晚双峰，2次/天
  晨峰: 10:10-11:15（上午工作开始后，整理前夜+上午动态）
  晚峰: 17:23-19:10（下班前，覆盖午后重要新闻）

单一主题（半导体热点）→ 晨报+晚报，2次/天
  晨报: 11:15（午前，覆盖隔夜海外半导体动态）
  晚报: 23:00（夜间，覆盖当日盘中所有重要事件）
```

**设计原则：**

1. **避开整点新闻高峰**：cron执行时间通常比目标发布时间早5-30分钟（生成+发布需要时间），AI热点04:00执行→05:04发出
2. **垂直内容选晨+晚而非均匀分布**：MLCC、原子级制造等需要"隔夜汇总+当日事件"两层覆盖，均匀分布反而丢失完整性
3. **财经比AI更密集**：财经新闻时效性更强（开盘/收盘时间锚点），所以每6小时一次而非8小时
4. **单一主题不超2次/天**：超过2次会出现内容重复，降低信息密度

**对Jerry的意义**

设计新的cron简报任务时，先确定内容类型（泛内容=4次/天，垂直内容=2次/天），再按上述时间槽位分配，避免拍脑袋定时间导致发布节奏混乱。

**延伸思考**

Cron执行时间和实际推送时间之间有约5-30分钟延迟（内容生成+发布到博客+发送飞书）。设计调度时应预留这个buffer，尤其财经新闻不应卡在09:00开盘前才推送（应选08:30执行，给内容生成和发布留足时间）。
