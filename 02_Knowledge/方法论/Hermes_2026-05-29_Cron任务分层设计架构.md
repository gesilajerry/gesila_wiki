# Cron任务分层设计架构

**背景**
Hermes每日执行14个定时任务，分布在05:01至21:10的时间轴上，形成完整的内容生产闭环。从早间任务到深夜归档，任务间有明确的时间顺序和依赖关系。

**核心洞察**

1. **时间轴分布（每日）**
   - 05:01 / 07:05：早间任务（内容预热）
   - 09:01：知识蒸馏（gesila_compile增量）
   - 09:11 → 11:34：上午任务（多批次内容生成）
   - 14:04：下午任务
   - 17:35：傍晚任务
   - 19:10 → 21:10：晚间任务（收尾）
   - 归档任务：结构层提炼（21:30）→ 输入层归档（时间不明）

2. **任务类型分层**
   - 内容生成层：早/午/晚内容推送（财经、MLCC、原子级制造、小红书等）
   - 知识管理层：增量蒸馏（每日09:00）
   - 归档层：输入层归档 + 结构层提炼（日内时间不明确）

3. **Cron Job配置存储**
   - 位置：`~/.hermes/cron/jobs.json`
   - 字段：id（注意不是job_id）、name、prompt、skills、schedule等
   - 修改方式：直接编辑JSON文件，通过job['id']做key映射

4. **任务间数据流**
   - Cron输出 → 归档文件（100%保留原始内容）
   - 归档日志 → 结构层提炼 → 知识卡片
   - 知识卡片 → Git push → Wiki平台展示

5. **防重复机制**
   - OpenClaw gateway内置cron调度 vs Hermes独立cron系统
   - 迁移时需暂停OpenClaw任务：`cronjob pause <job_id>`
   - 两者可并存，但需避免同一任务重复执行

**对Jerry的意义**
- 设计新cron任务时，先画时间轴分布图，避免任务扎堆
- 知识蒸馏（gesila_compile）放在09:00，恰好在上午内容任务之前
- 结构层提炼（21:30）是最后一道工序，在此之前归档必须完成

**延伸思考**
- 任务优先级：内容生成任务优先于归档任务（内容时效性 > 整理时效性）
- 失败重试：cron任务应有重试机制，特别是内容推送类
- 监控告警：任务失败需及时通知，否则深夜任务失败可能次日才发现
