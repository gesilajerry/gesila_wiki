# 小红书批量预生成-分散发布模式

**背景**
坨坨蔑夫斯基账号每天3篇内容（08:00视频 / 14:00图文 / 20:00视频），需要在前一天或当天早起一次性完成全部素材生成。如果每篇都等到发布时间才生成，会因为MiniMax API额度限制（每天2+2个视频片段）而无法保障3篇全部发布。

**核心洞察**

06:00预生成任务解决了内容生产与发布的节奏错配问题。其核心设计是"批量预生成 + manifest状态驱动 + 分散时间发布"：

1. **批量预生成**：06:00一次性生成当天全部3篇内容（文案+9张AI配图+音乐储备），利用凌晨低峰期窗口
2. **计数器机制**：publish_counter.txt管理篇号（1-16轮转），每篇按序号对应固定画家和画作，永不重复
3. **manifest状态追踪**：每篇内容在manifest.json中有独立状态字段（ready/script+images_ready），下游任务按状态判断是否可发布
4. **分散时间发布**：08:00/14:00/20:00三个发布任务只读取manifest和素材，不重新生成，职责单一

这种模式的关键价值：将资源消耗（MiniMax API调用）集中在一个时间窗口，将内容消费（用户看到）分散到全天。避免了发布时间争抢额度的问题，也保证了每日3篇的稳定更新节奏。

**对Jerry的意义**
这个模式让他名画账号能做到每天3篇稳定更新，而无需每天手动干预。如果未来要扩展到更多平台或账号，可以复制这套"预生成-分发"架构，只需修改manifest→各平台发布的连接器。

**延伸思考**
可以应用于：多语言内容批量生产、跨平台同一素材不同格式适配（如小红书图文vs抖音视频）、营销日历的提前备稿等场景。本质是把"硬deadline"变成"软deadline"，用提前量换稳定性和抗风险能力。
