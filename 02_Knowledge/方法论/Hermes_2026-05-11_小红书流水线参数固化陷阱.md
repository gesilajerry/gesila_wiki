# 小红书流水线参数固化陷阱

**背景**
每日自动运行的小红书图片生成流水线（xhs-image-gen-r3），用户指定了 4:3 横屏尺寸（1152×864），但脚本中 `SIZE` 变量被硬编码为 `"3:4"`，导致生成结果一直是 3:4 竖屏，直到本次执行才被发现并 patch。

**核心洞察**
多轮自动化的流水线最危险的敌人不是运行时错误，而是**参数固化后无人复核**。脚本在每次 cron 执行时不会报错（exit_code=0），图片也"成功生成"，但尺寸完全不符合预期。这种缺陷不会触发任何告警，只有人工比对输出才能发现。

流水线执行的关键监控点：
- 图片尺寸是最容易固化出错的参数，因为它是隐式约定而非显式输出
- 脚本内的硬编码常量（如 `SIZE = "3:4"`）不会产生任何日志或错误
- 每一轮脚本更新后，首次执行的输出必须有人工复核

**对Jerry的意义**
所有自动化脚本中的关键参数（尺寸、数量、格式）应该做成**配置文件或启动参数**，而不是硬编码。这样每次调整参数时只需修改一处，且修改记录可追溯。当前脚本的问题在于：修改了 `SIZE` 硬编码后，后续轮次才能自动生效，而不是立即生效。

**延伸思考**
在内容生产流水线的 QA 阶段，建议增加**自动化尺寸校验**：用 Python Pillow 读取生成图片的实际尺寸，与预期值对比，不匹配则告警并中止流水线。这比人工抽查更可靠。可以将这个检查封装成一个装饰器 `@verify_image_size(expected_ratio="4:3", expected_w=1152)` 应用于所有图片生成任务。
