# mmx搜索"-t 24h"时间过滤踩坑实录

**背景**
在使用mmx search命令进行AI/财经新闻监控时，一个看似合理的`-t 24h`时间过滤标志会导致搜索结果完全乱码——返回的是歌曲、医疗信息等毫不相关的内容。这是一个严重但隐蔽的bug，容易让没有防备的用户浪费大量时间排查其他原因。

**核心洞察**
问题出在mmx search的`-t 24h`参数实现逻辑上：当使用时间过滤时，搜索系统会触发与"新闻"无关的召回通道，导致返回结果与查询意图脱节。实测发现：

- 不加`-t 24h`，正常搜索"宏观经济 货币政策 金融市场 2026年5月"，返回高质量财经新闻
- 加上`-t 24h`，返回结果完全无关（歌曲名匹配、疾病名称匹配等）

根本原因是mmx search的时间过滤机制与关键词召回之间存在路由错误，时间约束反而成了噪声源，而非精排信号。

**正确替代方案**：
在查询关键词中直接加入中文日期约束，替代`-t 24h`标志。例如：
```python
# ❌ 错误：-t 24h 导致结果乱码
results = mmx_search("宏观经济 货币政策 金融市场", max_results=8)

# ✅ 正确：查询词中加日期
results = mmx_search("宏观经济 货币政策 金融市场 2026年5月", max_results=8)
```

其他已验证有效的中文日期约束写法：
- `"2026年5月21日 纳米制造 突破"` 用于当日新闻
- `"2026年5月 纳米制造 突破"` 用于月度新闻
- 使用中文实体名（如"本源悟空"而非"BQx量子计算机"）效果更佳

**对Jerry的意义**
Jerry的AI新闻简报系统依赖mmx search作为核心信源，这一bug直接影响每日简报的准确性。所有使用mmx search的新闻任务（AI热点推送、半导体热点、原子级制造科研等）都需要在查询词中加日期，而非依赖时间过滤参数。

**延伸思考**
这一踩坑经验具有普遍性：CLI工具的时间过滤参数可能在不同语种场景下表现差异巨大，中文场景下使用关键词内嵌日期约束是更可靠的选择。未来在引入新的搜索工具时，应优先测试时间过滤功能在目标语种下的表现。
