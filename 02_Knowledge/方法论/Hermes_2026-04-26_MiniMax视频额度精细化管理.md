# MiniMax Hailuo视频额度精细化管理

**背景**
每天需要生成2个视频片段（08:00和20:00篇），但MiniMax Hailuo视频额度非常有限：Hailuo-2.3-Fast 2个/天 + Hailuo-2.3 2个/天 = 每天最多4个片段。每周28个片段，刚好覆盖每天2篇×7天，没有一点冗余。

**核心洞察**

视频额度是最稀缺资源，需要精细化管理：

**额度结构（官方数据）**：
| 模型 | 每日额度 | 重置时间 |
|------|---------|---------|
| Hailuo-2.3-Fast | 2个/天 | 每日0点 |
| Hailuo-2.3 | 2个/天 | 每日0点 |
| **合计** | **4个/天** | 每日0点 |

**每片段规格**：约6秒，768p。生成30秒视频需要5个片段拼接。

**额度消耗策略**：
- 优先使用Fast模型（更快、成本更低）
- 每天固定消耗2个片段（08:00篇+20:00篇），留2个备用
- 若Fast额度耗尽，Fallback到普通Hailuo-2.3
- 若额度完全耗尽：视频篇自动降级为图文篇，不跳篇不重试

**关键陷阱**：
- 后台UI显示的"6小时53分钟后重置"不是真实重置间隔，是到午夜0点的倒计时
- 额度的重置是"每日0点"而非"每24小时"
- 音乐生成（Music-2.6）是独立额度，每天100首，与视频额度互不影响

**降级兜底设计**：
```json
// manifest.json中每篇的状态
"status": "ready"           // 正常状态
"status": "script+images_ready"  // 视频失败，降级图文
```

**对Jerry的意义**
这个模式让他清楚知道自己名画账号的视频产能上限：每天最多2个真实视频篇。如果想提高发布频率（比如每天3篇视频），要么打通视频片段的拼接发布流程（5个6秒片段→30秒长视频），要么接入其他视频API作为补充。

**延伸思考**
这是一个典型的"固定资源池+优先级队列"问题。当资源（视频额度）固定时，内容策略应该是：优先保证核心内容（名画故事视频），用图文作为降级兜底。未来扩展方向：本地视频生成（如Deforum、Stable Video Diffusion）作为自有算力补充，绕过API额度限制。

**标签**：Hermes × MiniMax × 视频生成 × 资源配额管理
