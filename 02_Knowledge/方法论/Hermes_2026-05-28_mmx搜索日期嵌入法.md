# mmx搜索日期嵌入法（cron自动化场景最佳实践）

**背景**
2026-05-21至今，`mmx search query -t 24h` 时间过滤标志在所有关键词组合下均返回完全无关内容（歌曲《24H》、尿量正常值等医疗/音乐内容），这是mmx搜索的已知bug。2026-05-26再次实测三组关键词（半导体/芯片/出口管制、晶圆代工/台积电/中芯国际、半导体国产化/AI芯片），全部8条结果均与目标无关，确认bug存在且无法绕过。

**核心洞察**
- **错误做法**：`mmx search query -t 24h --limit 8 "MLCC 被动元件"` → 返回歌曲/医疗内容
- **正确做法**：去掉 `-t 24h`，在query关键词中直接嵌入日期汉字形式
- **标准模式**：
  ```python
  from datetime import datetime
  today = datetime.now().strftime('%%Y年%%m月%%d日')
  # 三组并发搜索
  kw_groups = [
      f"半导体 芯片 美国出口管制 {today}",
      f"晶圆代工 台积电 中芯国际 {today}",
      f"半导体国产化 芯片设计 AI芯片 {today}",
  ]
  ```

**对Jerry的意义**
- 所有简报类cron任务（财经、MLCC、半导体、原子级制造）均依赖mmx搜索
- 日期嵌入法是这些cron任务正确运行的基础，必须固化到所有相关skill文档中
- 搜索结果默认按相关性排序，非时间排序；如需时间约束，加日期即可

**延伸思考**
- snippet含HTML标签（`</p><p>`），需用 `re.sub(r'<[^>]+>', '', text)` 彻底清洗
- 搜索结果为空时，尝试去掉具体日期改用月级别约束（如 `"2026年5月 纳米制造 突破"`）
- 中文日期约束比英文有效，中文实体名（如"汉原2号"、"本源悟空"）在搜索中国科技新闻时远比英文名有效
