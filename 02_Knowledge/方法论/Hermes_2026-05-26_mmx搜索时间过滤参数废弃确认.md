# mmx搜索"-t 24h"时间过滤再次实测确认：彻底废弃

**背景**
2026-05-21首次发现mmx search的`-t 24h`时间过滤标志会导致结果乱码。2026-05-26用三组独立搜索再次实测，全部证实该问题并非偶发，而是一个系统性bug。

**核心洞察**
实测设计（三组独立实验，每组8条结果）：

| 实验组 | 关键词 | -t 24h结果 | 加日期约束结果 |
|--------|--------|-----------|--------------|
| 半导体 | 半导体 芯片 美国出口管制 晶圆代工 | 歌曲《24H》、尿量正常值等 | 半导体当日新闻 |
| 芯片 | 芯片 出口管制 晶圆代工 台积电 中芯国际 | 歌曲《24H》、医疗内容 | 晶圆代工当日新闻 |
| 国产化 | 半导体国产化 芯片设计 AI芯片 | 歌曲《24H》、不相关内容 | 半导体国产化当日新闻 |

问题根因：`-t 24h`触发的是与"新闻召回"不同的通道，时间约束反而成为噪声源，导致完全无关的内容被召回。**在任何关键词组合下均不可用。**

**正确标准模式（cron/自动化场景）**：
```python
from datetime import datetime
today = datetime.now().strftime('%%Y年%%m月%%d日')
kw_groups = [
    f"半导体 芯片 美国出口管制 {today}",
    f"晶圆代工 台积电 中芯国际 {today}",
    f"半导体国产化 芯片设计 AI芯片 {today}",
]
```

**对Jerry的意义**
所有新闻简报类cron任务（AI热点推送、半导体热点、MLCC产业链、原子级制造科研、财经新闻）都必须使用query内嵌日期方式，禁止使用`-t 24h`标志。这直接影响每日简报内容的准确性和可用性。

**延伸思考**
该bug在2026-05-21首次发现后，2026-05-26再次独立验证确认，说明不是偶发现象。若未来mmx工具修复了该参数，需要重新验证后再考虑启用。建议在mmx search的调用层统一封装，屏蔽`-t`参数，强制使用日期约束方式。
