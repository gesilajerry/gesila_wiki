# mmx搜索：日期约束法替代-t24h标志

**背景**
2026-05-21首次发现并确认：mmx search命令的`-t 24h`时间过滤标志会导致结果完全乱码（返回歌曲《24H》、尿量正常值等医疗/音乐内容），在任何关键词组合下均不可用。2026-05-26再次实测三组搜索（半导体/晶圆代工/半导体国产化），全部8条结果均为无关内容。改用query内嵌日期方式后，三组搜索均返回正确的当日产业新闻。

**核心洞察**

**问题根源**：`mmx search`的`-t 24h`参数内部实现有缺陷，不执行真正的时间过滤，而是用错误算法匹配内容，导致结果与搜索意图完全无关。

**正确做法**：去掉`-t 24h`标志，改用查询关键词中直接包含日期约束。

```bash
# ❌ 错误：-t 24h 导致结果乱码
mmx search query -t 24h --limit 8 "MLCC 被动元件"

# ✅ 正确：查询词中加日期（年/月/日汉字形式）
mmx search query --limit 8 "MLCC 被动元件 村田 太阳诱电 2026年5月21日"
mmx search query --limit 8 "MLCC产能 扩产 价格 2026年5月"
```

**推荐的标准搜索模式（cron/自动化场景）**：
```python
from datetime import datetime
today = datetime.now().strftime('%Y年%m月%d日')
kw_groups = [
    f"半导体 芯片 美国出口管制 {today}",
    f"晶圆代工 台积电 中芯国际 {today}",
    f"半导体国产化 芯片设计 AI芯片 {today}",
]
```

**日期约束进阶技巧**：
1. 中文日期约束效果最好： `"2026年5月9日 纳米"` 优于 `"nanotech May 9 2026"`
2. 若当日无结果，改用月级别： `"2026年5月 纳米制造 突破"`（避免日期过细导致漏筛）
3. 搜索结果为空时，先确认是日期过细的问题，而非内容本身不存在

**对Jerry的意义**
这是所有新闻简报类cron任务（财经/半导体/MLCC/AI/原子级制造）的核心搜索方法论。错误使用`-t 24h`会导致整个简报内容质量崩溃。这条经验已被多次验证，应作为所有简报类任务的固定执行标准。

**延伸思考**
这一踩坑经验有更普适的意义：工具的某个参数报错/失效时，不要尝试修复参数本身，而是寻找功能等效的替代方案。`-t 24h`的本意是获取过去24小时的内容，替代方案是让LLM根据搜索结果的日期字段自行过滤，而不是依赖工具的时间参数。
