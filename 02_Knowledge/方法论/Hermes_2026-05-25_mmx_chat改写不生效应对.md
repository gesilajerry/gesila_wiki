# mmx text chat 改写不生效的应对策略

**背景**
使用 MiniMax CLI 的 `mmx text chat` 命令对文案进行小红书风格改写时，部分情况下会返回原文而非改写后的内容。症状是命令执行成功（exit_code 0），但输出内容与输入完全相同，没有实现风格迁移。

**核心洞察**
mmx text chat 有两种工作模式：
1. **改写模式**：输入原文 + 指令 → 输出改写版本
2. **透传模式**：无法识别指令时 → 原样返回输入内容

触发透传模式的场景：当指令不够明确、或 chat 模型判断不需要改写时，会直接返回原文而不报错。

**替代方案**
当 `mmx text chat` 返回原文时，切换到手动编写策略：

```bash
# 方案1：明确指定改写风格
mmx text chat --prompt "将以下文案改写成小红书风格：文艺、情感化、有画面感，每句话不超过20字：[原文]"

# 方案2：改用 mmx 生成
mmx image gen "描述画面" --style "梵高"

# 方案3：手动编写（最可靠）
# 直接根据主题手动撰写小红书风格文案
```

手动编写要点：
- 每句话不超过 20 字（符合小红书阅读习惯）
- 使用 emoji 增强视觉节奏
- 第一句必须抓眼球（问题/感叹/对比）
- 留白要足够（断行多）

**对Jerry的意义**
小红书梵高图文流水线的文案环节高度依赖 mmx text chat，当 chat 返回原文时会导致整篇文案质量下降。掌握手动编写方法可作为保底策略，确保每日发布不中断。

**延伸思考**
这个问题本质是 LLM 判断"是否需要改写"的阈值问题。可以通过更明确的指令（如"务必改写，不得原样返回"）来提高改写率，但最可靠的还是准备好风格模板直接套用。
