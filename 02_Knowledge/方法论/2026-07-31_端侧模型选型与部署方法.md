# 端侧模型选型与部署方法

## 背景

2026-07-31 在 8GB Mac 上完成 Gemma 3 4B 全流程部署实战后，提炼出的可复用方法论：从模型选型、镜像下载、llama-server 调参到验证清理的完整决策链。

## 核心步骤

### 第一步：按硬件内存选模型档位
- 内存预算 = 权重 + KV cache + 系统占用
- **8GB：只选 4B 级 Q4_K_M**（权重 ~2.5GB，可全 GPU）
- 16GB+：8B Q4_K_M 可全速（~5GB 权重）
- 永远不要用 8GB 机器硬跑 8B——OOM 或 3 t/s，两者都不可用

### 第二步：按场景选模型家族
- **agent / 工具调用场景 → Qwen3 系列**（工具调用强化训练，实测完美返回 tool_calls）
- 多模态（文本+图像）→ Gemma 3 4B；多模态+音频 → Gemma 3n E4B
- 纯聊天/翻译等无工具需求 → 任意 4B 级均可
- **务必实测工具调用**：curl 发 tools 请求看 `finish_reason` 是否为 `tool_calls`，防幻觉

### 第三步：镜像下载（国内网络）
- **首选 ModelScope**（modelscope.cn）：5-20MB/s 稳定，`curl -L -C - -o` 支持断点续传
- hf-mirror.com：小文件可用，大文件（500MB+）不稳（FileMetadataError / 速度慢），仅作备选
- URL 模式：`https://modelscope.cn/models/unsloth/<模型>-GGUF/resolve/master/<文件>`
- 下载前先验证：`curl -sIL` 看 content-length 与磁盘剩余空间对比

### 第四步：llama-server 调参模板
```bash
# 8GB Mac 4B 模型（全 GPU）
llama-server -m ~/models/<model>-q4km.gguf --port 8080 \
  -ngl 99 -c 2048 -t 4 --load-mode mlock -cb -ctk q8_0 -ctv q8_0 \
  --alias <model> --api-key <key>
```
- `-ngl 99`：全部层放 GPU（Apple Silicon 统一内存最快）
- `-c 2048`：8GB 机器上下文上限，别超过
- `--load-mode mlock`：锁定内存防 swap（v10180 起替代已废弃的 --mlock）
- `-ctk/-ctv q8_0`：KV cache 量化省内存
- 参数检查清单：llama-server 启动日志确认 `model loaded` + `listening on` 再测试

### 第五步：验证与清理
- OpenAI 兼容验证：`curl http://localhost:8080/v1/chat/completions`
- 实验结束恢复原状：kill 服务 → 删模型文件 → brew uninstall（本案例释放 14.5GB）

## 对Jerry的意义

这套方法把"本地部署"从试错变成流水线：选型有据（内存档位 × 场景家族 × 实测验证）、下载有镜像优先级、调参有模板、结束有清理清单。下次任何端侧模型需求（Trae 接入、离线 agent）直接套用。

## 延伸思考

端侧模型的价值在隐私与零成本，但 8GB 硬件的体验上限（速度、上下文）与云端 API 差距明显。务实策略：**隐私敏感/高频小任务用本地 4B，重任务用云端**，混合路由。
