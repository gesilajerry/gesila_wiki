# 资料权限四级体系的合理性评估

## 一、现状描述

信息安全是企业核心竞争力的重要组成部分。Creatom建立了基于"全体员工-部门成员-项目成员-管理层"的四级资料权限体系，配合"机密-秘密-内部-公开"的保密等级制度，构成了公司信息安全的防护网。

### 1.1 四级权限体系架构

**权限级别定义**：

| 权限级别 | 定义 | 覆盖范围 |
|---------|------|---------|
| 全体员工 | 公司所有正式员工 | 全员 |
| 部门成员 | 特定部门的员工 | 部门内 |
| 项目成员 | 特定项目的参与人员 | 项目内 |
| 管理层 | 部门负责人及以上 | 管理岗位 |

**权限矩阵**：

| 文件类型 | 全体员工 | 部门成员 | 项目成员 | 管理层 | 外部 |
|---------|---------|---------|---------|--------|------|
| 公司规章制度 | 可读 | 可读 | 可读 | 可读/编辑 | - |
| 项目主页 | 可读 | 可读 | 可读/编辑 | 可读/编辑 | - |
| 设计图纸 | - | 可读 | 可读/编辑 | 可读 | - |
| BOM清单 | - | - | 可读/编辑 | 可读 | - |
| 成本预算 | - | - | 项目经理 | 可读 | - |
| 商务合同 | - | - | 项目经理 | 可读 | - |
| 客户信息 | - | - | 销售 | 可读 | - |
| 专利文件 | - | 可读 | 可读 | 可读/编辑 | - |
| 实验数据 | - | 可读 | 可读/编辑 | 可读 | - |
| 市场调研 | 可读 | 可读 | 可读 | 可读/编辑 | - |
| 人事档案 | - | - | - | 人事/总经理 | - |
| 财务报表 | - | - | - | 财务/总经理 | - |
| 交付文件 | - | 可读 | 可读 | 可读 | 客户（部分） |

### 1.2 保密等级制度

**四级保密等级**：

| 保密等级 | 定义 | 内容范围 |
|---------|------|---------|
| 机密级 | 泄露将造成重大损失 | 成本价格、客户合同金额、核心技术参数、供应商价格 |
| 秘密级 | 泄露将造成较大损失 | 设计图纸、BOM清单、实验数据、客户信息 |
| 内部级 | 仅限公司内部使用 | 公司制度、项目进度、会议纪要 |
| 公开级 | 可对外公开 | 公司介绍、产品宣传资料、对外公告 |

**制度依据**：
- 《商业秘密管理制度》
- 《关于强化生产车间保密管理的通知》（20251231）

### 1.3 VPN与信息安全管理

**VPN管理制度**：
- 实行VPN一人一号制度（《关于实行VPN一人一号的通知》-20250709）
- 严禁将公司技术资料外传
- 生产车间需强化保密管理

### 1.4 执行现状

**权限配置情况**：
- 飞书/Confluence平台已按权限矩阵配置基础权限
- 部分敏感文件设置了额外的访问控制
- 权限变更流程不明确，存在滞后现象

**保密管理情况**：
- 保密制度已传达至全员
- 生产车间保密管理有所加强
- 缺乏定期的保密检查和审计

**问题事件**：
- 偶发文件误发、权限配置错误事件
- 离职人员权限回收存在延迟
- 跨部门协作时的权限申请流程繁琐

## 二、问题分析

### 2.1 权限粒度偏粗

**部门级权限过于宽泛**：

"部门成员"这一权限级别涵盖了部门内所有岗位，但不同岗位对信息的需求差异很大。例如，研发部门内，机械工程师和电气工程师对图纸的需求不同；同一部门内，普通员工和小组长的权限也应有所区分。

当前权限体系缺乏岗位级别的细分，导致"一刀切"现象严重。

**项目权限边界模糊**：

"项目成员"的定义不够清晰。是只要参与过项目就算项目成员，还是必须正在参与项目？项目结束后权限是否保留？这些问题缺乏明确规定。

实际执行中，项目权限往往"只增不减"，员工参与过的项目越来越多，权限范围越来越大，形成权限膨胀。

### 2.2 权限与保密等级脱节

**双重体系缺乏联动**：

权限体系和保密等级是两个独立运行的体系。一个文件可能被标记为"秘密级"，但权限配置可能允许"部门成员"访问，这与保密等级的要求可能不一致。

**机密级信息保护不足**：

机密级信息（如成本价格、客户合同金额）理论上应该严格管控，但权限矩阵中"成本预算"的权限是"项目经理"，这一权限设置是否足够严格？项目经理是否有必要知道所有成本细节？

**缺乏动态调整机制**：

员工的权限一旦设定，很少进行调整。但员工的岗位、项目参与情况在不断变化，静态的权限配置难以适应动态的管理需求。

### 2.3 权限申请与审批流程繁琐

**临时权限申请困难**：

跨部门协作、临时项目支持时，员工需要申请临时权限。但权限申请流程不明确，往往需要层层审批，影响工作效率。

**权限审批标准不清**：

权限申请由谁审批？审批的标准是什么？这些问题缺乏明确规定。实际执行中，权限审批往往依赖于个人关系，缺乏客观标准。

**权限回收不及时**：

员工调岗、离职时，权限回收存在延迟。特别是项目权限，员工离职后往往仍然保留历史项目的访问权限，存在信息泄露风险。

### 2.4 缺乏权限审计机制

**权限使用无记录**：

谁访问了什么文件？什么时候访问的？这些关键信息缺乏记录。一旦发生信息泄露事件，难以追溯。

**权限配置无审核**：

权限配置是否正确？是否存在过度授权？缺乏定期的权限审核机制。

**异常访问无预警**：

员工突然大量下载文件、非工作时间访问敏感文件等异常行为，缺乏自动预警机制。

### 2.5 技术支撑不足

**权限管理分散**：

文件分布在飞书、Confluence、本地服务器等多个平台，权限管理分散，难以统一管控。

**缺乏权限管理工具**：

没有专门的权限管理系统，权限配置主要依靠人工操作，效率低、易出错。

**权限与业务系统脱节**：

权限管理与项目管理、人力资源管理等系统没有集成，员工岗位变动时权限不能自动调整。

## 三、理论支撑

### 3.1 最小权限原则

**最小权限原则（Principle of Least Privilege, POLP）**是信息安全的基本原则，要求：

- 每个用户只拥有完成工作所必需的最小权限
- 权限应根据工作需求动态调整
- 临时权限应及时回收

当前公司的权限体系存在明显的过度授权现象，与最小权限原则不符。

### 3.2 基于角色的访问控制（RBAC）

**RBAC模型**将权限与角色关联，用户通过分配角色获得权限。RBAC的核心要素包括：

- **用户（User）**：系统的使用者
- **角色（Role）**：一组权限的集合
- **权限（Permission）**：对资源的访问许可
- **会话（Session）**：用户与角色的映射

当前公司的权限体系虽然有一定的角色概念（全体员工、部门成员等），但角色定义过于粗放，缺乏细粒度的角色划分。

### 3.3 基于属性的访问控制（ABAC）

**ABAC模型**根据属性（用户属性、资源属性、环境属性）动态决定访问权限。ABAC的优势在于：

- 灵活性高，支持复杂的访问控制策略
- 支持动态授权
- 支持上下文感知

当前公司的权限体系是静态的，缺乏ABAC的动态授权能力。

### 3.4 信息安全风险管理

**ISO 27001**信息安全管理体系强调基于风险的方法：

- 识别信息安全风险
- 评估风险影响
- 选择适当的控制措施
- 持续监控和改进

当前公司的权限管理缺乏风险评估机制，权限配置主要依赖经验而非风险分析。

## 四、优化方案

### 4.1 细化权限粒度

**五级权限模型**：

| 权限级别 | 定义 | 示例 |
|---------|------|------|
| 公司级 | 全员可访问 | 公司制度、公告 |
| 部门级 | 部门内可访问 | 部门工作计划 |
| 岗位级 | 特定岗位可访问 | 岗位操作手册 |
| 项目级 | 项目成员可访问 | 项目文档 |
| 个人级 | 仅本人可访问 | 个人工作文档 |

**岗位权限矩阵**：

在部门级权限基础上，增加岗位级权限控制：

| 岗位 | 设计图纸 | BOM清单 | 成本信息 | 客户信息 |
|------|---------|---------|---------|---------|
| 机械工程师 | 机械部分可读写 | 可读写 | 不可见 | 不可见 |
| 电气工程师 | 电气部分可读写 | 可读写 | 不可见 | 不可见 |
| 项目经理 | 只读 | 只读 | 项目成本可见 | 项目客户可见 |
| 销售 | 不可见 | 不可见 | 不可见 | 负责客户可见 |

### 4.2 建立权限与保密等级联动机制

**保密等级-权限映射表**：

| 保密等级 | 最小权限要求 | 额外控制措施 |
|---------|-------------|-------------|
| 机密级 | 岗位级+审批 | 水印、下载限制、访问审计 |
| 秘密级 | 项目级 | 访问日志、定期审核 |
| 内部级 | 部门级 | 基本访问控制 |
| 公开级 | 公司级 | 无额外控制 |

**敏感信息细分**：

对机密级信息进一步细分，实施差异化保护：

- **战略机密**：公司战略、并购信息 - 仅限高管
- **商业机密**：成本价格、供应商价格 - 财务+采购负责人
- **技术机密**：核心技术参数 - 技术负责人+核心研发
- **客户机密**：合同金额、客户战略 - 销售负责人+项目经理

### 4.3 建立动态权限管理机制

**项目权限生命周期**：

```
项目立项 → 权限开通 → 项目执行 → 权限维持 → 项目结束 → 权限降级 → 权限回收
```

- **项目立项**：根据角色自动开通权限
- **项目执行**：权限正常使用
- **项目结束**：权限降级为只读
- **项目归档3个月后**：权限回收

**岗位变动权限自动调整**：

与HR系统对接，岗位变动时自动调整权限：
- 调岗：原岗位权限降级，新岗位权限开通
- 离职：所有权限冻结，工作交接后回收
- 晋升：权限自动升级

**临时权限管理**：

- 临时权限有效期：最长30天
- 临时权限需说明申请理由
- 临时权限到期自动回收
- 临时权限使用审计

### 4.4 完善权限申请与审批流程

**权限申请流程**：

```
申请人填写申请表 → 直属上级审批 → 数据Owner审批 → 权限管理员配置 → 申请人确认
```

**审批权限矩阵**：

| 申请类型 | 直属上级 | 部门负责人 | 数据Owner | 权限管理员 |
|---------|---------|-----------|----------|-----------|
| 部门内权限 | 审批 | - | - | 执行 |
| 跨部门权限 | 审核 | 审批 | - | 执行 |
| 机密级权限 | 审核 | 审核 | 审批 | 执行 |

**审批时效要求**：

- 直属上级：1个工作日内
- 部门负责人：2个工作日内
- 数据Owner：3个工作日内

### 4.5 建立权限审计机制

**访问日志记录**：

记录所有文件访问行为：
- 访问人
- 访问时间
- 访问文件
- 访问类型（查看/下载/编辑）
- 访问IP

**定期权限审核**：

- **月度审核**：检查新增/离职人员权限
- **季度审核**：检查项目权限合规性
- **年度审核**：全面权限审计

**异常访问预警**：

设置预警规则：
- 非工作时间访问敏感文件
- 短时间内大量下载文件
- 访问权限外的文件
- 异常IP地址访问

**权限报告**：

- 每月生成权限使用报告
- 每季度生成权限合规报告
- 每年生成权限管理评估报告

### 4.6 强化技术支撑

**统一权限管理平台**：

建立统一的权限管理平台，整合各系统的权限管理：
- 飞书权限管理
- Confluence权限管理
- 文件服务器权限管理
- VPN权限管理

**权限管理自动化**：

- 与HR系统集成，自动同步人员信息
- 与项目管理系统集成，自动管理项目权限
- 与审批系统集成，自动处理权限申请

**敏感信息保护技术**：

- 文档水印：机密文件自动添加访问人水印
- 下载限制：机密文件限制下载，仅支持在线查看
- 截屏控制：敏感页面禁止截屏
- 外发控制：文件外发需审批，自动添加水印

## 五、实施路径

### 5.1 第一阶段：现状梳理与风险评估（1个月）

**工作内容**：
- 全面梳理现有权限配置
- 识别过度授权和权限缺失问题
- 评估各类信息资产的风险等级
- 调研员工对权限管理的满意度

**可量化指标**：
- 完成100%权限配置梳理
- 识别至少20个权限问题
- 完成风险评估报告

### 5.2 第二阶段：制度完善（1个月）

**工作内容**：
- 修订《商业秘密管理制度》
- 制定《权限管理规范》
- 设计权限申请、审批、回收流程
- 制定权限审计制度

**可量化指标**：
- 完成制度文件修订
- 完成流程设计
- 完成全员培训

### 5.3 第三阶段：系统建设（2个月）

**工作内容**：
- 选型或开发权限管理平台
- 整合各系统权限管理
- 开发权限审计功能
- 开发异常预警功能

**可量化指标**：
- 权限管理平台上线
- 实现权限管理自动化
- 实现访问日志记录

### 5.4 第四阶段：权限整改（2个月）

**工作内容**：
- 按新规范重新配置权限
- 清理过度授权
- 补充权限缺失
- 建立项目权限生命周期管理

**可量化指标**：
- 权限配置合规率≥95%
- 过度授权问题清零
- 项目权限生命周期管理覆盖率100%

### 5.5 第五阶段：持续运营（长期）

**工作内容**：
- 每月进行权限审核
- 每季度进行权限审计
- 每年进行权限管理评估
- 持续优化权限管理策略

**可量化指标**：
- 权限配置合规率≥98%
- 权限申请处理时效≤3天
- 异常访问事件响应时间≤2小时

## 结语

资料权限四级体系的合理性评估揭示了一个核心问题：权限管理不是简单的"能访问"或"不能访问"，而是需要在安全与效率之间找到平衡点。

通过细化权限粒度、建立联动机制、实施动态管理、完善审批流程、建立审计机制、强化技术支撑，公司有望构建一个既安全又高效的权限管理体系。

权限管理的优化是一个持续的过程，需要随着业务发展和组织变化不断调整。只有建立科学的权限管理机制，才能在保护核心信息资产的同时，支撑业务的高效运转。
