# 多频道新闻简报双分发架构

**背景**
Hermes 在2026-05-15当天运行了17个cron任务，其中12个新闻推送任务（AI/财经/半导体/MLCC/原子级制造）。每条简报都同时发到 Koala 博客和飞书群聊，形成一套标准化的双分发架构。

**核心洞察**
每条简报（财经/AI/半导体/原子级制造/MLCC）都走同一套标准化流水线：

1. **搜索采集**：mmx search 多关键词并行（5-6条/简报），去重合并
2. **内容生成**：筛选近24小时事件，格式化 markdown
3. **博客发布**：Koala API（`/api/discussion`）发布到指定 forum_id（1=市场销售/2=综合管理）和 group_ids（12=专业知识）
4. **飞书发送**：同时发送 markdown 原文到 `oc_1e92781` 群聊

执行摘要用表格展示（渠道|状态|详情），每条简报的核心要点用 8 条列表呈现。发布后返回文章 ID（如 `kg1Lkpuvdkm4QMis`），飞书端显示 `code=0`。

关键设计：博客发布用 forum_id=1（市场销售）和 group_ids=[12]（专业知识）路由到正确的分类；而飞书发送则原封不动转发 markdown 原文，两者互补。

**对Jerry的意义**
这套架构让每天的产业动态自动沉淀到内网知识库（Koala博客）并同步通知到飞书群聊。Koala 博客的文章 ID 可以追溯原始发布，飞书通知则提供实时推送。两者缺一不可——博客是沉淀层，飞书是通知层。

**延伸思考**
可以扩展到更多垂直领域简报（新能源汽车、医疗器械、消费电子），每个领域用不同的 forum_id+group_ids 路由。简报格式可以标准化为模板，减少每次的 prompt engineering 成本。飞书端可进一步实现文章 ID 点击跳转博客详情。

**标签**：Hermes × 飞书API × 博客发布 × 简报流水线
