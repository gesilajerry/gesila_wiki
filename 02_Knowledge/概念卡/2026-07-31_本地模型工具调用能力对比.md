# 本地模型工具调用能力对比

## 背景

2026-07-31 在 8GB Mac 上用 llama-server（OpenAI 兼容 API）对 Gemma 3 4B 和 Qwen3 8B 做工具调用（function calling）实测：`tools=[get_weather]` + `tool_choice=auto`，问"查询北京的天气"。

## 核心洞察

**洞察1：Gemma 3 4B 工具调用不可用** — 完全忽略 tools 参数，直接编造数据（幻觉输出"墨迹天气"的假天气），不返回 tool_calls。原因：4B 级 Gemma 3 的工具调用能力未经强化训练，且 4B 小模型对复杂 JSON schema 遵循能力弱。

**洞察2：Qwen3 8B 工具调用完美** — 返回 `finish_reason: tool_calls`，正确输出 `{"city": "北京"}` JSON 参数，且带 reasoning_content 思考过程（先确认参数要求再构造 JSON）。Qwen3 系列把工具调用作为训练强化重点，函数遵循能力显著强于同代竞品。

**洞察3：能力 ≠ 可用** — Qwen3 8B 工具调用虽完美，但 8GB 机器上 -ngl 18 只有 3 t/s，Trae 里无法实际使用。**模型选型要同时满足"能力"与"速度"两个约束**：8GB 硬件上二者交集是 Qwen3-4B（工具调用强化 + 全速 25+ t/s）。

## 对Jerry的意义

本地 agent 场景（Trae/IDE 接入、自动化任务）的模型选型标准：**工具调用能力是硬指标**。Gemma 系列（尤其小参数）不适合 agent，Qwen3 系列是本地 agent 的首选。测试方法可复用：用 curl 直连 OpenAI 兼容端点发 tools 请求，看 finish_reason 是否为 tool_calls。

## 延伸思考

小模型工具调用幻觉（编造不存在的工具结果）比大模型更危险——错误以"看似正常"的方式呈现。生产环境接入前必须实测工具调用链路，不能只看跑分。
