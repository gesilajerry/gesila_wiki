# 【AI工作流插件开发（寄生策略）】

## 一句话总结
不为独立App获客烧钱，而是为Cursor/VS Code/Figma/Notion等高流量平台开发插件，在巨头流量池中"寄生"截流，获客成本近乎为零。

## 启动清单（3步内可执行）
1. **选定平台+痛点**：从Cursor/VS Code/Figma/Notion/Shopify中选1个你最熟悉的平台，找到1个高频痛点（如"把DeepSeek连接到Excel"），用JS/TS/Python写一个周末MVP
2. **上架插件市场**：提交到对应平台的插件商店（VS Code Marketplace / Figma Community / Chrome Web Store等），写清功能说明和使用截图
3. **冷启动引流**：在Reddit/即刻/V2EX/小红书发帖展示插件效果，同时在Product Hunt做一次Launch

## 所需工具（全部免费）
- **VS Code Extension API**：开发VS Code插件的官方SDK，文档完善
- **Figma Plugin API**：开发Figma插件的官方框架
- **GitHub**：代码托管 + 开源获取Star和用户信任
- **TypeScript/JavaScript**：大多数插件平台的标准开发语言
- **Chrome DevTools**：调试插件的前端界面和交互

## 变现路径
- **第1周**：完成MVP开发并上架插件市场，获取首批用户反馈，验证需求真实性
- **第2-4周**：根据反馈迭代功能，建立免费增值模式（基础功能免费 + 高级功能订阅），目标首月100+活跃用户
- **第2个月**：推出订阅制（$5-15/月），目标月收入$500+；同时开发第二个插件形成产品矩阵

## 风险提示
- **平台政策变动**：平台可能修改API或调整商店规则导致插件失效 → 避坑：多平台布局，不依赖单一平台；关注平台开发者动态
- **同质化竞争**：热门平台插件数量激增，容易被模仿 → 避坑：深耕垂直场景，做"连接器"类插件（打通两个工具的壁垒），建立切换成本
- **付费转化率低**：免费用户多但愿意付费的少 → 避坑：确保免费版有明确的功能限制（而非时间限制），让用户自然感受到付费的价值
