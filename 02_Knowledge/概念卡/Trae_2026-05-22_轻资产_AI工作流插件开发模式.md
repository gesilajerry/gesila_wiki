# 【AI工作流插件开发模式】

## 一句话总结
不做独立App，为Cursor/VS Code/Figma/Notion等高流量平台开发插件，在巨头流量池中截流变现的寄生策略。

## 启动清单（3步内可执行）
1. 第一步：安装Node.js + npm，运行`npm install -g yo generator-code`安装脚手架，生成插件框架并运行调试
2. 第二步：挖掘3个痛点（写下自己遇到的3个不爽 + Reddit搜索验证 + Marketplace评论区找需求）
3. 第三步：实现最小功能并发布（修改extension.ts实现核心功能 → 打包vsce package → 注册Azure DevOps Publisher → 发布到Marketplace）

## 所需工具（全部免费）
- **VS Code**：代码编辑器，插件开发主战场
- **GitHub Copilot Free**：AI辅助编程，替代方案Codeium/Tabnine
- **Figma Free**：UI设计工具
- **Lucide Icons/Heroicons**：免费开源图标素材
- **LemonSqueezy/Paddle**：支付接入，抽成模式无 upfront
- **Vercel/Cloudflare Workers**：后端服务免费额度

## 变现路径
- 第1周：免费插件上线，积累首批用户，目标10+下载
- 第2-4周：收集反馈迭代优化，发布v0.2，准备Pro功能
- 第2个月：推出付费版，目标首单收入¥100-500，稳定期¥500-2000/月

## 风险提示
- 坑1：功能越做越大永远不上线 → 设定硬性deadline，MVP必须一周内上线，只保留核心功能30%
- 坑2：选错平台流量枯竭 → 优先VS Code/Cursor（开发者付费意愿强），慎选Chrome扩展
- 坑3：定价失误收入微薄 → 采用"免费+Pro"模式，参考竞品定价，提供年付折扣
- 坑4：忽视用户反馈闭门造车 → 上线即开放GitHub Issues，每周回复5个用户评论
- 坑5：法律合规风险 → 仔细阅读平台开发者协议，隐私政策透明，避免侵权素材
