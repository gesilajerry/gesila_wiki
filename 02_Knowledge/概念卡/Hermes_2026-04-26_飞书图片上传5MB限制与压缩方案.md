# 飞书图片上传5MB限制与macOS压缩方案

**背景**
在向飞书会话发送图片时，遇到过多次上传失败（code 234006），日志显示是图片体积过大。飞书开放平台对上传的图片有约5MB的大小限制，超过就会被拒绝。这个问题在原图（名画高清图11.3MB）上传时尤为突出。

**核心洞察**

飞书API的图片上传限制是强约束，必须在发送前压缩到5MB以下。经验值：

| 图片类型 | 典型大小 | 处理方式 |
|---------|---------|---------|
| 名画原图（Wikimedia高清） | 8-15MB | 必须压缩 |
| AI生成配图 | 0.5-3MB | 通常无需压缩 |
| 压缩后安全范围 | <4.5MB | 上传稳定 |

**macOS内置压缩方案**（无需安装任何工具）：
```bash
sips -s formatOptions 70 /path/to/input.jpg --out /path/to/output.jpg
```
`formatOptions 70` 表示JPEG质量压缩到70%，大多数图片可以从8MB+压到3-4MB，人眼几乎看不出差异。这个方法比ImageMagick更快，且是macOS预装。

**压缩判断逻辑**（建议写入脚本）：
```python
import os
if os.path.getsize('/tmp/xhs_original.jpg') > 5 * 1024 * 1024:
    # 压缩
    os.system('sips -s formatOptions 70 /tmp/xhs_original.jpg --out /tmp/xhs_original_compressed.jpg')
    shutil.move('/tmp/xhs_original_compressed.jpg', '/tmp/xhs_original.jpg')
```

**对Jerry的意义**
这个知识点直接解决了他小红书发布流程中的卡点——每次发名画原图都可能遇到上传失败。加了压缩步骤后，08:00篇（星月夜4.64MB）和未来更大的图片都能稳定上传。这是一个可以写入飞书发送技能的标准前置步骤。

**延伸思考**
其他可能遇到类似限制的场景：微信公众号图片限制（10MB）、企业微信（5MB）、邮件附件（20MB）等，都可以参考"先判断大小，再决定是否压缩"的逻辑。FFmpeg处理视频帧时也可以用`sips`做缩略图压缩。
