## 二、失败任务根因分析

### 1. idle timeout（模型空闲超时）- 最高频错误

**受影响的Cron任务：**
- `AI热点推送 04:00` — 连续失败（5月8日、9日）
- `AI热点推送 10:00 / 12:00` — 多次失败
- `MLCC产业链晨报 10:15` — 连续失败
- `输入层归档 09:00` — 多次失败
- `半导体热点晨报 11:15` — 连续失败

**根因分析：**
- 模型在执行长任务（如xreach多轮搜索→整理→推送）时触发idle timeout
- 任务运行时长通常在300-600秒，但某些任务在200秒左右即超时
- 凌晨时段（02:00-06:00）的任务超时率显著高于白天，因该时段上下文缓存可能较冷

**建议修复：**
- 增加`models.providers.<id>.timeoutSeconds`至600秒以上
- 或对xreach多轮搜索任务拆解为子任务（搜索→整理→推送分步）

### 2. 数据源不可用

**受影响的Cron任务：**
- `财经新闻推送 08:00`（5月9日）— NewsAPI/Yahoo Finance返回429，Reuters/WSChina/Investing.com连接超时
- `MLCC产业链晚报`（5月8日）— X API TLS handshake timeout，Google News JS渲染无法抓取

**根因分析：**
- 外网直连受限（X/Twitter API TLS握手超时）
- 境外新闻源在中国大陆出口有限流/反爬
- 已有备选方案（东方财富、新浪财经RSS、Google财经RSS）可用

**已验证可用备选：**
- 东方财富实时API（行情数据）
- Google财经RSS（中文财经新闻）
- CNBC/BBC/FT RSS（英文财经）
